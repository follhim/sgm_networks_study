2.3 Creating Demographic Variables

Our survey asked participants to select all race/ethnicity, sexual identity, and religious affiliation categories that applied to them (i.e., check-all-that-apply items), while gender identity was a single-select item. This means the raw variables need to be collapsed into single, categorical variables before we can use them in analysis. Below we walk through that process for each of our four key demographic variables: race/ethnicity, gender identity, sexual orientation, and religious identity/affiliation.

2.4 Race and Ethnicity

Race and ethnicity was captured across 11 check-all-that-apply items (rei_1-rei_11), corresponding to White, Black, Asian, Pacific Islander, Native American, Native Hawaiian, MENA, Latine, Multiracial, Another racial identity, and Prefer not to answer, respectively. We’ll collapse these into a single race variable across four steps.

Step 1: Combine selections into a single string

First we recode missing values on each rei_* item to 0 (not selected), then paste together the labels of every category a participant selected into one string (race_combo). Respondents who selected nothing are labeled "None selected".

Click to see code 
p2_data <- p2_data %>%
  mutate(
    across(all_of(paste0("rei_", 1:11)), ~ replace_na(.x, 0)),

    race_combo = paste0(
      ifelse(rei_1 == 1, "White_", ""),
      ifelse(rei_2 == 1, "Black_", ""),
      ifelse(rei_3 == 1, "Asian_", ""),
      ifelse(rei_4 == 1, "Pacific Islander_", ""),
      ifelse(rei_5 == 1, "Native American_", ""),
      ifelse(rei_6 == 1, "Native Hawaiian_", ""),
      ifelse(rei_7 == 1, "MENA_", ""),
      ifelse(rei_8 == 1, "Latine_", ""),
      ifelse(rei_9 == 1, "Multiracial_", ""),
      ifelse(rei_10 == 1, "Another racial identity_", ""),
      ifelse(rei_11 == 1, "Prefer not to answer_", "")
    ),

    race_combo = case_when(
      race_combo == "" ~ "None selected",
      TRUE ~ str_remove(race_combo, "_$")
    )
  )

Step 3: Collapse into final race/ethnicity categories

Using the frequencies above, we collapse race_combo into a smaller set of meaningful categories (race2):

  • Single-selection responses of White, Black, Asian, and Latine each become their own “Non-Latine” category (Latine becomes “Latine Non-White”); MENA stays on its own.
  • “White” + “Latine” is common enough on its own to warrant its own category (“White Latine”).
  • Every other multi-selection combination, along with single selections of smaller groups (Native American, Pacific Islander, Multiracial, Another racial identity), is combined into “Multiracial/ethnic”.
  • “Prefer not to answer” and blank responses are kept as their own categories.

We also set factor levels so tables and plots display in a consistent order.

      race2,

2.5 Gender Identity

Gender identity (gi) was a single-select item, so no combining is needed here. We collapse the original response codes into three broader categories: cisgender men, cisgender women, and transgender/gender-diverse (tgd) individuals, combining response codes 5 through 10 (e.g., trans man, trans woman, nonbinary, genderqueer, etc.) into the tgd category due to small cell sizes.

Click to see code 
p2_data <- p2_data %>%
  mutate(gender = case_when(
    is.na(gi) ~ NA,
    gi %in% c(1) ~ "cisman",
    gi %in% c(4) ~ "ciswoman",
    gi %in% c(5, 6, 7, 8, 9, 10) ~ "tgd",
    TRUE ~ NA
  ))

2.6 Sexual Orientation

Sexual orientation was another check-all-that-apply item, with 10 identity options (si_1-si_10): Gay, Lesbian, Bisexual, Pansexual, Heterosexual/straight, Queer, Asexual, Demisexual, Questioning/unsure, and Another sexual identity. Because participants could select multiple identities that overlap in meaningful ways (e.g., someone selecting both “Queer” and “Bisexual” is likely using “Queer” as an umbrella term rather than a distinct identity), we build this variable up over several passes, with each pass collapsing the previous version a bit further.

Step 1: Combine selections into a single string

As with race/ethnicity, we first recode missing values to 0, then paste together every selected identity into a single string (sex_id_combo), which becomes our raw sex1 variable. We also count how many identities each person selected (selection_count), which we’ll use in later steps to decide how to collapse combinations.

Click to see code 
p2_data <- p2_data %>%
  mutate(
    across(all_of(paste0("si_", 1:10)), ~ replace_na(.x, 0)),

    sex_id_combo = paste0(
      ifelse(si_1 == 1, "Gay_", ""),
      ifelse(si_2 == 1, "Lesbian_", ""),
      ifelse(si_3 == 1, "Bisexual_", ""),
      ifelse(si_4 == 1, "Pansexual_", ""),
      ifelse(si_5 == 1, "Heterosexual/straight_", ""),
      ifelse(si_6 == 1, "Queer_", ""),
      ifelse(si_7 == 1, "Asexual_", ""),
      ifelse(si_8 == 1, "Demisexual_", ""),
      ifelse(si_9 == 1, "Questioning/unsure_", ""),
      ifelse(si_10 == 1, "Another sexual identity_", "")
    ),

    sex_id_combo = case_when(
      sex_id_combo == "" ~ "None selected",
      TRUE ~ str_remove(sex_id_combo, "_$")
    ),

    selection_count = rowSums(
      cbind(si_1, si_2, si_3, si_4, si_5, si_6, si_7, si_8, si_9, si_10) == 1,
      na.rm = TRUE
    ),

    sex1 = sex_id_combo
  )

Step 2: Treat “Queer” and “Heterosexual/straight” as modifiers

Looking at the raw combinations above, two patterns stand out: people frequently pair “Queer” with a more specific identity (e.g., “Queer_Bisexual”), and some pair “Heterosexual/straight” with another identity (e.g., “Heterosexual/straight_Questioning/unsure”). In both cases the more specific identity is likely the better descriptor, so we recode these pairings to that other identity. The one exception is “Queer” + “Asexual”, which we keep coded as “Queer”.

Note that the two rules are not symmetric:

  • Queer is paired with all 8 other identities (Gay, Lesbian, Bisexual, Pansexual, Asexual, Demisexual, Questioning/unsure, Another sexual identity).
  • Heterosexual/straight is only explicitly paired with 5 (Gay, Lesbian, Bisexual, Pansexual, Questioning/unsure). Combinations of Heterosexual/straight with Asexual, Demisexual, Another sexual identity, or Queer are not covered by this recode.
  • For three-way combinations of Queer + Heterosexual/straight + one more identity, only + Bisexual and + Questioning/unsure are explicitly handled; other three-way combinations are not.

Any combination not covered by these rules simply falls through unchanged (kept as the raw sex_id_combo string). Single selections and “None selected” also pass through unchanged. This gives us sex2.

Click to see code 
p2_data <- p2_data %>%
  mutate(
    sex2 = case_when(
      # Handle missing/none selected
      is.na(sex_id_combo) ~ NA_character_,
      sex_id_combo == "None selected" ~ "None selected",

      # Single selections - keep as is
      selection_count == 1 ~ sex_id_combo,

      # Rule 1: If combination includes "Queer" and one other identity, use the other identity
      selection_count == 2 & grepl("Queer", sex_id_combo) & grepl("Gay", sex_id_combo) ~ "Gay",
      selection_count == 2 & grepl("Queer", sex_id_combo) & grepl("Lesbian", sex_id_combo) ~ "Lesbian",
      selection_count == 2 & grepl("Queer", sex_id_combo) & grepl("Bisexual", sex_id_combo) ~ "Bisexual",
      selection_count == 2 & grepl("Queer", sex_id_combo) & grepl("Pansexual", sex_id_combo) ~ "Pansexual",
      selection_count == 2 & grepl("Queer", sex_id_combo) & grepl("Asexual", sex_id_combo) ~ "Queer", # Special case: Queer + Asexual = Queer
      selection_count == 2 & grepl("Queer", sex_id_combo) & grepl("Demisexual", sex_id_combo) ~ "Demisexual",
      selection_count == 2 & grepl("Queer", sex_id_combo) & grepl("Questioning/unsure", sex_id_combo) ~ "Questioning/unsure",
      selection_count == 2 & grepl("Queer", sex_id_combo) & grepl("Another sexual identity", sex_id_combo) ~ "Another sexual identity",

      # Rule 2: If combination includes "Heterosexual/straight" and one other identity, use the other identity
      selection_count == 2 & grepl("Heterosexual/straight", sex_id_combo) & grepl("Gay", sex_id_combo) ~ "Gay",
      selection_count == 2 & grepl("Heterosexual/straight", sex_id_combo) & grepl("Lesbian", sex_id_combo) ~ "Lesbian",
      selection_count == 2 & grepl("Heterosexual/straight", sex_id_combo) & grepl("Bisexual", sex_id_combo) ~ "Bisexual",
      selection_count == 2 & grepl("Heterosexual/straight", sex_id_combo) & grepl("Pansexual", sex_id_combo) ~ "Pansexual",
      selection_count == 2 & grepl("Heterosexual/straight", sex_id_combo) & grepl("Questioning/unsure", sex_id_combo) ~ "Questioning/unsure",

      # Rule 3: If both Queer AND Heterosexual/straight with one other, use the other identity
      selection_count == 3 & grepl("Queer", sex_id_combo) & grepl("Heterosexual/straight", sex_id_combo) & grepl("Bisexual", sex_id_combo) ~ "Bisexual",
      selection_count == 3 & grepl("Queer", sex_id_combo) & grepl("Heterosexual/straight", sex_id_combo) & grepl("Questioning/unsure", sex_id_combo) ~ "Questioning/unsure",

      # All other combinations remain as they are
      TRUE ~ sex_id_combo
    )
  )

Step 3: Simplify to single vs. multiple identities

For a simpler descriptive variable, we collapse everything that still contains multiple identities (indicated by an underscore in sex2) into a single “Multiple Sexual Identities” category, keeping single identities as they are. This gives us sex3.

Step 4: Initial monosexual vs. plurisexual grouping

For our key sexual orientation variable, we group identities into monosexual (attraction to one gender: gay, lesbian, heterosexual/straight) versus plurisexual (attraction to multiple genders: bisexual, pansexual, demisexual), while keeping asexual, queer, questioning/unsure, and “another sexual identity” as their own distinct categories. Combinations that include a plurisexual identity (bisexual, pansexual, or demisexual) anywhere are coded as plurisexual. “Gay” + “Lesbian”, and monosexual + asexual combinations, are coded as monosexual. “Queer” + “Asexual” is coded as queer. Anything not covered by these rules is temporarily labeled “Other” so we can review it in the next step. This gives us sex4.

Click to see code 
p2_data <- p2_data %>%
  mutate(
    sex4 = case_when(
      # Missing values
      is.na(sex2) ~ NA_character_,
      sex2 == "None selected" ~ "None selected",

      # Monosexual identities
      sex2 == "Gay" ~ "Monosexual",
      sex2 == "Lesbian" ~ "Monosexual",
      sex2 == "Heterosexual/straight" ~ "Monosexual",
      sex2 == "Gay_Lesbian" ~ "Monosexual", # Gay+Lesbian combination
      sex2 == "Lesbian_Gay" ~ "Monosexual", # Gay+Lesbian combination

      # Monosexual + Asexual combinations
      sex2 == "Gay_Asexual" ~ "Monosexual",
      sex2 == "Asexual_Gay" ~ "Monosexual",
      sex2 == "Lesbian_Asexual" ~ "Monosexual",
      sex2 == "Asexual_Lesbian" ~ "Monosexual",

      # Plurisexual identities
      sex2 == "Bisexual" ~ "Plurisexual",
      sex2 == "Pansexual" ~ "Plurisexual",
      sex2 == "Demisexual" ~ "Plurisexual",
      grepl("Bisexual", sex2) ~ "Plurisexual", # Any combination with Bisexual
      grepl("Pansexual", sex2) ~ "Plurisexual", # Any combination with Pansexual
      grepl("Demisexual", sex2) ~ "Plurisexual", # Any combination with Demisexual

      # Keep specific identities as is
      sex2 == "Asexual" ~ "Asexual",
      sex2 == "Queer" ~ "Queer",
      sex2 == "Questioning/unsure" ~ "Questioning/unsure",
      sex2 == "Another sexual identity" ~ "Another sexual identity",

      # Special case: Queer + Asexual = Queer
      sex2 == "Queer_Asexual" ~ "Queer",
      sex2 == "Asexual_Queer" ~ "Queer",

      # All other cases
      TRUE ~ "Other"
    )
  )

Step 5: Final monosexual vs. plurisexual categorization

Reviewing the “Other” cases above, we found a few more combinations that clearly belong in the “Monosexual” category (e.g., “Gay” or “Lesbian” paired with “Questioning/unsure”, or “Gay”/“Lesbian” + “Queer” + “Asexual”). We add those rules here to produce our final variable, sex5. Anything still unaccounted for is kept as “Other” (rather than set to missing), since these are genuinely ambiguous combinations worth reviewing manually if needed.

p2_data <- p2_data %>%

2.7 Religious Identity

Religious affiliation was captured as check-all-that-apply items at two time points: current affiliation (rsi_curr_1-rsi_curr_26) and past affiliation (rsi_past_1-rsi_past_26). From these, we build a religious-trajectory variable, relid_life, classifying each respondent as Never, Former, or Current religious. This section mirrors the coding scheme used in a related analysis, Patterns of Religious Engagement, which uses this exact same raw dataset (sgm_ego_spss_DID_07_24_25.sav). Ambiguous or unclassifiable cases from that analysis were manually reviewed by two coders, and we reuse those resolved codes here rather than re-doing the review from scratch — because the row-based ID scheme lines up across both projects (both assign internal_id/ID as 1:nrow() on the full, unfiltered sample immediately after import), the manual codes can be joined back in directly.

Note

How is religious trajectory (relid_life) coded?

  1. Classify affiliation per wave: Each respondent’s checked religious-affiliation items are collapsed to a single primary category for the past and current waves (rel_past_id2/rel_curr_id1), using priority-ordered rules: non-religious/secular items first (Agnostic, Atheist, Non-religious, None, Secular Humanist), then Spiritual, then each denomination/tradition.
  2. Group into broad categories: rel_curr_id1/rel_past_id2 are grouped into rel_curr_id (current) and rel_past_id (past). Only Buddhism, Daoism, Hinduism, Islam, Judaism, Paganism, Sikhism, and Unitarian are grouped into Other; only Protestant, Orthodox, LDS, and Other Christian are grouped into Christian. Roman Catholic, Not Religious, and Spiritual keep their own labels. Bahai, Confucianism, Jainism, Native American, and Zoroastrianism are not grouped — they pass through as their own raw labels, since the original scheme has no catch-all rule for them.
  3. Classify trajectory: Comparing past vs. current group yields relid_life:
    • Never: not religious/spiritual in both waves
    • Former: religious (Christian/Roman Catholic/Other) in the past, not religious/spiritual now
    • Current: religious (Christian/Roman Catholic/Other) in both waves
    • Everything else is NA — this includes people who switched between traditions, people who became religious (not religious/spiritual in the past but religious now), and anyone whose past or current category is one of the five ungrouped raw labels above.
  4. Manual review of ambiguous/NA cases: All NA respondents were independently reviewed by two coders across all religion responses (screen/RelID_Coding_062426.xlsx). Cases where both coders agreed on Current, Former, or Never were resolved; contradictions, missing data, or unresolved disagreements stayed NA. Resolved codes are merged back in by respondent ID and override the automatic classification only where a resolved code exists — everyone else keeps their automatic (possibly still-NA) classification.

Current Affiliation

We first collapse the 26 current-affiliation checkboxes into a single label per person (rel_curr_id1). Non-religious/secular selections take priority — if a respondent checked any of Agnostic, Atheist, Non-religious, None, or Secular Humanist, they’re coded "Not Religious" regardless of what else they checked. We also keep the specific secular label on its own (not_rel) for reference. After Spiritual and the non-religious block, each remaining tradition is checked in turn.

We then group rel_curr_id1 into a broader rel_curr_id variable. As noted above, only 8 smaller/less-represented traditions get folded into "Other", and only 4 Christian sub-traditions get folded into "Christian" — Bahai, Confucianism, Jainism, Native American, and Zoroastrianism are left as their own raw labels rather than grouped anywhere.

Religious Trajectory (relid_life)

We compare rel_past_id to rel_curr_id to classify each respondent’s trajectory. Only three combinations are explicitly handled — Never (not religious/spiritual at both waves), Former (religious at some point among Christian/Roman Catholic/Other, not religious/spiritual now), and Current (religious among Christian/Roman Catholic/Other at both waves). Everything else — including newly-religious respondents (not religious/spiritual in the past but religious now), anyone who switched between the grouped categories, and anyone whose past or current affiliation is one of the five ungrouped raw labels (Bahai, Confucianism, Jainism, Native American, Zoroastrianism) — falls to NA, to be resolved by the manual coding step below.

Click to see code 
p2_data <- p2_data %>%
  mutate(
    relid_life = case_when(
      # Never: not religious (or spiritual) in both waves
      rel_past_id %in% c("Not Religious", "Spiritual") &
        rel_curr_id %in% c("Not Religious", "Spiritual") ~ "Never",

      # Former: religious in the past, not religious (or spiritual) now
      rel_past_id %in% c("Christian", "Roman Catholic", "Other") &
        rel_curr_id %in% c("Not Religious", "Spiritual") ~ "Former",

      # Current: religious in the past AND still religious now
      rel_past_id %in% c("Christian", "Roman Catholic", "Other") &
        rel_curr_id %in% c("Christian", "Roman Catholic", "Other") ~ "Current",

      # Everything else (e.g., switched traditions, became religious, or
      # involves an ungrouped raw label) → NA, resolved manually below
      TRUE ~ NA
    )
  )

Manual Coding

Because we knew our algorithm would not be 100% effective, every respondent left NA above was independently reviewed by two coders (SK, NT) against their full set of religion responses, as part of the Patterns of Religious Engagement analysis. That review’s resolved codes live in the Final column of screen/RelID_Coding_062426.xlsx (copied into this project’s screen/ folder), keyed by respondent ID. Rows with a resolved Final value (Current, Former, or Never) override the automatic classification above; rows where the coders disagreed, lacked data, or otherwise couldn’t resolve the case are NA in Final and are left untouched — they keep whatever relid_life value they already had (which, since they all started out NA, means they simply remain NA).

Apply Manual Coding

The join key is internal_id, the sequential row number assigned to the full, unfiltered sample in 1_import.qmd. Because this section runs before any row filtering (the “Addressing Errors” step below hasn’t happened yet), and because internal_id was assigned immediately after import (mirroring how the ID was assigned in the Patterns of Religious Engagement project), the two ID schemes line up and the join is safe.

Click to see code 
rel_curr_id_code <- openxlsx::read.xlsx(here("screen", "RelID_Coding_062426.xlsx"))

manual_codes <- rel_curr_id_code %>%
  filter(!is.na(Final)) %>%
  select(internal_id, Final)

p2_data <- p2_data %>%
  left_join(manual_codes, by = c("internal_id" = "internal_id")) %>%
  mutate(relid_life = coalesce(Final, relid_life)) %>%
  select(-Final)
